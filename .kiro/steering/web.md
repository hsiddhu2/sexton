# Cemetery rules

- Grave form encodes state, nothing else (R-UI-1, version 0.5): a rounded stone with a party hat and flowers for Alive, a tilted stone with a hand clawing out of the dirt for Restless, a cross for Haunted, a cracked tilted stone with a lounging skeleton in a onesie for Dead, an open grave with a dancing devil-costumed zombie and a pink glow for Possessed. Colour follows state. Every grave of one State looks the same; only the animation phase and the Dancer schedule differ.
- A ghost above a grave means one or more advisories. Nothing else is a ghost.
- No continuous visual encodings. No tombstone height, no opacity scales. Categorical only. The three depth Tiers (scene/tiers.ts) are categorical: Possessed and Dead in front at scale 1, Haunted and Restless in the middle at 0.8, Alive at the back at 0.64. A grave's Tier follows its scan-date State, rows are centred, triage order holds within a Tier and in the keyboard order, and grave rectangles never overlap.
- Order graves by triage: Possessed first, then state from least healthy to most healthy (Dead, Haunted, Restless, Alive), then advisory severity, then transitive reach, then name.
- Readable without the legend. If a first-time viewer cannot tell which grave to fix first, the encoding is wrong.
- WCAG 2.1 AA contrast. Every grave reachable by keyboard. prefers-reduced-motion respected.
- 300 graves without visible lag. Canvas or WebGL for the scene, DOM for the drawer.
- The scene is a 2D canvas (scene/Scene.tsx). Grave buttons in overlay/GraveButtons.tsx give keyboard focus and aria-labels.
- Web imports only types from @sexton/api.
- Web fetches only addresses that pass checkScanUrl in load/use-scan-loader.ts: a scan file on the page's own origin (the demo is /demo/scan.json) or the API base from load/api-base.ts. The API base is a same-origin path such as /api or an https URL.
- The drawer opens a pull request with POST to the API base plus /remediate. The body is { repo, package }. Show the button only for a hosted scan whose response has actions.remediate true.
- The header links the evidence pack as JSON and Markdown downloads.
- ESLint bans dangerouslySetInnerHTML, innerHTML, outerHTML, insertAdjacentHTML and node: imports in packages/web/src. Render scan text as text only.
- Scenery is seeded (scene/scenery-seed.ts). No Math.random. Stars and grass depend on the scene width only, never on the scan.
- The Shadow under a grave and the Stone texture are decoration, the same for every grave of a State. They use fixed alpha bytes from scene/palette.ts. No opacity scales.
- The Evidence tooltip is DOM, not canvas: role="tooltip", shown on grave hover and on keyboard focus, dismissed by Escape. It has pointer-events none, is 240 px wide, is anchored at its own Cell and kept inside the Scene (it may extend past a scaled Cell), and is not shown while the drawer is open.
- The PR preview parses with drawer/markdown.ts, which handles exactly what the engine's pr-body.ts emits. A link is made only for an https:// address, with target="_blank" and rel="noopener noreferrer". Output is React elements only.
- The Result area (the outcome of opening a pull request) sits outside the scrolling drawer body, so it stays in view.
- The header is not inert while the drawer is open. Only the scene is. A press on the Repository URL box closes the drawer and focuses the box.
- The scene is full-bleed: no horizontal padding on main.
- At 360 px there is no horizontal scroll, with the drawer closed, open or the legend open. Below 512 px the drawer is full width.
- Every colour is a token in scene/palette.ts. A new token joins the contrast tests. styles.css holds no colour literal. The palette is night-only.
- The scan time is shown in a <time> element with a machine-readable dateTime.
- Grass is short seeded tufts along the row lines and one line near the bottom of the ground (scene/scenery-seed.ts, drawn by drawTufts in scene/draw.ts). Tufts depend on the scene width only.
- The ground reaches the bottom of the viewport. hooks/use-free-height.ts gives the free height and planScene takes it as minHeight. Grave positions do not change.
- The scrubber (time/Scrubber.tsx) is a native range input named "History date" with aria-valuetext. Its stops come from time/stops.ts: the start, one stop for each change of state, ghost or version, and the scan date. It is not rendered when the response has no timelines.
- Web holds no state rule. The Engine writes Segments into the scan response (timelines). time/form-at.ts looks up the Segment at the chosen instant. Never copy a state rule into web.
- Triage order and grave positions always use the scan date. Only form, colour, ghost and the inscription version follow the chosen date.
- The drawer always shows the scan date. A note under the scrubber says so when an earlier date is chosen.
- Two forms are added and neither changes the grave form of a State. The Not-published form is an unmarked mound with no ghost, for a package whose installed version is not yet published on the chosen date. The pull request marker is a pennant beside the grave, and the grave button name ends in "pull request opened". It is not a ghost. Both have a legend chip.
- The marker comes from the scan response (pullRequests, read from the remediation log) and from pull requests opened in this session.
- The burial plays once for each package and loaded scan after a pull request is opened, when the drawer closes or at once if it is closed. It lasts 1200 ms in three fixed phases: the stone sinks, a mound shows, then the stone returns with the pennant. Under prefers-reduced-motion there is no burial animation. The burial never changes the state, shape or fill of a grave.
- A replay is a scan response loaded from /replay/axios.json or /replay/keyv.json on the page origin. The buttons are "axios, Mar 2026" and "keyv, Aug 2026", in a group named by the visible label "Replay an attack" in the Footer bar. The addresses ?replay=axios and ?replay=keyv load them. Any other replay value loads nothing.
- A replay opens at its first Stop. Every other scan opens at its scan date.
- The Play control (time/Scrubber.tsx, time/play.ts, time/use-play.ts) is a native button in the Footer bar before the History date label, the date and the slider, shown only for more than one Stop. Its name is "Play" or "Pause". It moves one Stop every 1,500 ms and stops at the last Stop. Play at the last Stop restarts at the first. The slider, Back to now and a new load pause it. Each start, step, end and pause is announced in a polite live line, never role="status". It never starts on its own.
- When the response has timelinesOmitted "too-large", the line "History is not shown for this scan because it is too large." takes the place of the scrubber.
- At 1440 by 900 on the demo at its scan date the canvas top is at most 190 px. The header holds the wordmark, the summary, the evidence links, the form, a disabled "Sound off" button (described "Sound arrives in the next release"), Serious mode and the Legend. The Footer bar (footer.night-footer, after main) holds Play, History date, the date and slider (or the omitted history line) and "Replay an attack". At 960 px and wider both stay in view (sticky) and each is one row; narrower, both scroll with the page. The ground runs to the bottom of the viewport, under the footer.
- The palette is the night of cemetery-undead: Alive #8fe3d0, Restless #e69f00, Haunted #56b4e9, Dead #bfb8ad, Possessed #cc79a7 on a violet sky with an orange harvest moon. The five state colours stay at least 8 apart in CIEDE2000 under simulated protanopia, deuteranopia and tritanopia (test/colour-vision.test.ts). The Lantern glow and the Possessed glow are Glow stops in the contrast tests, and a grave has at most one glow.
- Fonts are self-hosted under public/fonts with their OFL files: Pirata One for the wordmark, IM Fell English SC for grave names, IM Fell English italic for epitaphs, Instrument Sans for the interface. No font request leaves the page origin.
- Characters are original vector art (scene/characters/vector.ts) at 12 Poses a second, driven by one clock in Scene.tsx that only repaints the canvas and stops while the page is hidden. Under prefers-reduced-motion every Character holds one still Pose and the bats hold still. A Dead skeleton dances 2 s in every 12 s for one Dead grave in five (at least one when any Dead grave exists), chosen from a seed of the package name. The ghost is original art; never draw or embed the Kiro logo.
- The backdrop (church, tree, fence, bats, fog, vignette, grain, the cratered moon) depends on the width only and is drawn under every grave. The hovered or focused grave gets the Lantern glow.
- The tooltip and the drawer show "Here lies <name> <version>" and, unless Serious mode is on, one Punchline from the table in epitaph/epitaph.ts, chosen by State and the state reason's text. A reason the table does not know gets no Punchline. Serious mode is a header toggle (aria-pressed), off by default, stored under sexton:serious with every storage access guarded.
- A replay screen shows the banner text "Reconstructed from public reports. Not a live scan." (replay/ReplayBanner.tsx). A source link is made only for an https:// address.
