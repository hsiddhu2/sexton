# Bugfix Requirements Document
## Introduction
`evaluateState` in `packages/engine/src/state.ts` assigns Dead to any package whose last publish is more than 24 months old, and Restless to any package whose last publish is 12 to 24 months old. Age alone therefore marks small, finished packages as dead.
Evidence: a live scan of https://github.com/expressjs/express on 21 Nov 2026 rated 16 of 44 direct dependencies Dead. Most had one reason only, "last publish more than 24 months ago": depd 2.0.0, escape-html, vary, fresh, parseurl and once. These are small, finished packages that the Express team still uses. They fail the default policy (forbid Possessed and Dead), and 15 of them got "no safe version" because no newer release exists. A reviewer who scans a well-known repository sees false alarms, and the remediation list offers nothing that can be done.
The bug condition is: the installed version is not deprecated, no Possessed rule matches, the last publish is more than 24 months before the reference time, and the package has no advisory or the advisories signal is unavailable. In that case the current code gives Dead.
The fix changes R-ST-2 so that age alone gives Restless. Dead needs deprecation, or age together with at least one advisory of any severity. The 12 to 24 months Restless rule is removed, because a release gap under 24 months is normal for a finished package. The constant `DEAD_AFTER_MONTHS` becomes `STALE_AFTER_MONTHS` and `RESTLESS_AFTER_MONTHS` is removed. Everything derived from states is recomputed from the recorded fixtures, and the text that states the old rule is updated. No deploy is part of this spec.
## Bug Analysis
### Current Behavior (Defect)
1.1 WHEN the installed version is not deprecated, no Possessed rule matches, the last publish is more than 24 months before the reference time, and the package has no advisory or the advisories signal is unavailable THEN the system assigns Dead with the reason "last publish more than 24 months ago"
1.2 WHEN a small finished package such as depd 2.0.0, escape-html, vary, fresh, parseurl or once is rated Dead from age alone THEN the system fails the default policy for it and plans a remediation that ends in "no safe version", because nothing newer exists
1.3 WHEN the installed version is not deprecated, no Possessed rule matches, and the last publish is 12 to 24 months before the reference time THEN the system assigns Restless with the reason "last publish between 12 and 24 months ago", although a release gap under 24 months is normal for a finished package
1.4 WHEN the last publish is more than 24 months before the reference time and the package also has an advisory THEN the system assigns Dead with the reason "last publish more than 24 months ago", which does not name the advisory
### Expected Behavior (Correct)
2.1 WHEN the installed version is not deprecated, no Possessed rule matches, the last publish is more than 24 months before the reference time, and the advisories signal is available with no advisory THEN the system SHALL assign Restless with the reason "no release in 24 months" and SHALL NOT assign Dead
2.2 WHEN the installed version is not deprecated, no Possessed rule matches, the last publish is more than 24 months before the reference time, and the advisories signal is unavailable THEN the system SHALL assign Restless with the reason "no release in 24 months", because the second Dead branch cannot fire without advisory data
2.3 WHEN the installed version is not deprecated, no Possessed rule matches, the last publish is more than 24 months before the reference time, and the installed version has at least one advisory of any severity, Unknown included THEN the system SHALL assign Dead with the reason "no release in 24 months and an open advisory", ahead of the Haunted rule
2.4 WHEN the installed version is not deprecated, no Possessed rule matches, and the last publish is not more than 24 months before the reference time THEN the system SHALL NOT use the age of the last publish in any rule, so a last publish 12 to 24 months ago and a missing, null or future last publish give the same state
2.5 WHEN the engine is imported THEN the system SHALL export `STALE_AFTER_MONTHS` equal to 24 and SHALL NOT export `DEAD_AFTER_MONTHS` or `RESTLESS_AFTER_MONTHS`, and no source or test file SHALL import the removed names
2.6 WHEN the demo scan, the demo evidence, the golden evidence pack and report, `expected-states.json` and the policy fixture results are recomputed from the recorded fixtures with no network THEN the system SHALL show colors 1.4.0 as Restless with "no release in 24 months" and event-stream 3.3.6 as Dead with "no release in 24 months and an open advisory"
2.7 WHEN a package moves out of Dead or Haunted because of the new rule THEN the system SHALL propose no remediation for it, because only Haunted, Dead and Possessed packages get a plan
2.8 WHEN a reader opens the README state table, R-ST-2 in `docs/requirements.md`, requirement 11 of the health-scoring spec, the States section of `.kiro/steering/product.md`, or smoke check 12 of `build/infra/10-deploy.md` THEN the system SHALL present the new rule and no text SHALL state that age alone gives Dead or that 12 to 24 months gives Restless
### Unchanged Behavior (Regression Prevention)
3.1 WHEN a maintainer change in the last 90 days, a provenance regression or a new install script is present THEN the system SHALL CONTINUE TO assign Possessed with the same reason text, ahead of every other rule
3.2 WHEN the installed version is deprecated and no Possessed rule matches THEN the system SHALL CONTINUE TO assign Dead with the reason "installed version is deprecated"
3.3 WHEN the installed version is not deprecated, the package is not stale, and it has an advisory of severity High or Critical THEN the system SHALL CONTINUE TO assign Haunted with the reason "advisory of severity High or Critical"
3.4 WHEN the package is not stale and has an advisory of severity Moderate or Low, and none of High or Critical THEN the system SHALL CONTINUE TO assign Restless with the reason "advisory of severity Moderate or Low", and an Unknown-severity advisory alone on a package that is not stale SHALL CONTINUE TO give Alive
3.5 WHEN the last publish, deprecated and advisories signals are all unavailable and no Possessed rule matched THEN the system SHALL CONTINUE TO assign Restless with the reason "all state signals unavailable"
3.6 WHEN the state function is evaluated twice on equal inputs and an equal reference time THEN the system SHALL CONTINUE TO give equal results
3.7 WHEN two evaluations differ only in the last publish date THEN the system SHALL CONTINUE TO give the older date a state that is never healthier, with health order Possessed, Dead, Haunted, Restless, Alive from least to most healthy
3.8 WHEN a repository has no `sexton.policy.yml` THEN the system SHALL CONTINUE TO apply the default policy that forbids Possessed and Dead, and `sexton.policy.yml` in this repository SHALL CONTINUE TO hold its `max_age_months` rule of 24, which flags stale packages as a policy choice and not as a state
3.9 WHEN a package is Haunted, Dead or Possessed THEN the system SHALL CONTINUE TO plan remediation for it by the existing rules, and recorded upstream fixtures SHALL CONTINUE TO be used unchanged, with no re-recording from the network
